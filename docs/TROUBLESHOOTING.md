# 故障排查

## 页面没有打开

确认已完整解压并通过 `Start-MortalSim.cmd` 启动，检查安全软件是否隔离了 `_internal` 中的 DLL。手动打开启动器日志中的 `127.0.0.1` 地址。仍失败时从 PowerShell 运行 `MortalSim.exe` 并保留完整错误文本。

## CUDA 不可用

先运行 `nvidia-smi`，再查看诊断页的 Compute Capability。v0.3 Formal Lite 只接受 `8.9`（RTX 40），且不会使用 CPU 或 PyTorch 回退。更新 NVIDIA 驱动后重启；不要为 Portable 额外安装 `requirements-lock.txt` 或 CUDA Toolkit。

## Formal Lite 不可用

诊断页会分别报告缺失文件、SHA 不匹配、ABI 不一致、非 SM89 和 CUDA 初始化失败。不要单独替换 `model.dll` 或任一运行时 DLL；它们必须和 `runtime_manifest.json` 属于同一构建。重新下载 ZIP 并校验 SHA256。

## 模型导入失败

只接受标准 Mortal v4 / 256 channels / 54 blocks `.pth`。受限读取器不会执行权重携带的代码；缺字段、未知 pickle 全局、shape 不符、损坏文件和额外张量都会拒绝。Lite 包不提供模型下载地址，也不包含模型。

## 模拟失败

保存运行 ID、错误信息、Build ID、Artifact SHA、GPU/驱动信息和 `%LOCALAPPDATA%\\MortalSim\\logs`，再提交 GitHub Issue。不要上传模型、个人牌谱或敏感文件。

## Bot 的巡目、座次和牌河时序

`/sim` 中 `x` 是目标家的巡目（1..18），`seat=东/南/西/北` 是当前局的座次。
四段 `河=` 和四项 `P` 点数按当前东、南、西、北排列；当前东家始终是庄家。
未副露的摸牌后切牌决策中，自家已有 `x-1` 张弃牌，当前顺序排在自家前面的玩家有
`x` 张，后面的玩家有 `x-1` 张。吃碰响应可以打断对手的巡次，以最后一张实际弃牌为准。

例如，`E3-1 seat=南 x=2 河=2z,9st/7p/2z/9m` 的牌河张数是
`2/1/1/1`。东家已打第 2 张，南家正在作第 2 巡的切牌决策，西、北家各只打过 1 张。
完整四家牌河会原样校验，不会自动补出缺少的弃牌，也不会截掉未来弃牌。
空牌河可保留对应的斜杠分段，或使用四个明确的座次标签。
已有副露历史的时序暂不支持，不能按闭门手牌的轮转顺序代替。

API 的 `target_seat` 与四家牌河数组使用固定玩家编号，而不是当前座次。
Bot 会统一转换一次：`庄家编号 = 局号 - 1`，
`玩家编号 = (庄家编号 + 当前座次) % 4`，其中当前东、南、西、北为 `0/1/2/3`。
上述东三局的庄家编号为 `2`、南家编号为 `3`；这不表示当前西家坐庄。
直接调用 API 时，目标、牌河和供牌来源必须使用同一套编号。

若现场报错与同一命令的本地复现不一致，请核对实际启动目录、Git 提交、加载的
`parser.py` / `service.py` 以及原生扩展文件，而不只查看工作目录的分支名。
合并 PR 后，源码部署需要在运行目录更新代码、使用同一 Python 环境重新编译原生扩展，
再重启 Bot 和 API 进程。只拉取 `main` 不会包含尚未合并的 PR。

开发环境可用 `python tools/run_pr42_seat_cases.py --output output/seat-review`
复跑原始报告用例和构造回归用例；需要本机 CUDA、原生扩展和相应模型。
输出目录必须没有同名历史数据库，以避免混入旧样本；非 Windows 环境可用
`--font` 指定中文字体。脚本经过 API 请求模型序列化后直接调用本地 worker，
不等于验证线上 QQ 或 HTTP 服务已经部署成功。
